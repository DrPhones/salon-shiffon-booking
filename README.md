# صفحة حجز صالون شيفون

الصفحة **طلب حجز ذكي عبر واتساب (Smart Booking Request)**، وليست نظام حجز لحظي: لا يوجد backend ولا جدول موظفات ولا تحقق آلي من التوفر. التأكيد النهائي تقوم به موظفة الصالون عبر واتساب.

- الإنتاج: https://chiffon9.com/ (Cloudflare Workers static assets، يُنشر تلقائيًا من فرع `master` عبر Workers Builds؛ الإعداد في `wrangler.jsonc`).
- الرابط القديم https://drphones.github.io/salon-shiffon-booking/ يُحوَّل إلى الدومين الجديد من فرع `gh-pages-redirect`.
- `index.html` — هيكل الصفحة: مقدمة بعرض الشاشة، الكتالوج، ونموذج طلب الحجز.
- `assets/site.css` — التصميم العاجي الجديد والخطوط المحلية والاستجابة للهاتف.
- `assets/booking.js` — الكتالوج وقواعد طلب الحجز وحفظ المسودة والقياس.
- `assets/hero-3d.js` — مشهد الشيفون المجسّم باستخدام Three.js وWebGL2.
- `assets/experience.js` — التنقل وتهيئة المشهد دون تعطيل الحجز.
- `legacy/index.html` — نسخة مؤرشفة من التصميم السابق، غير قابلة للفهرسة (`noindex,nofollow`) وتحمل تنبيهًا يوجّه للصفحة الحالية.
- ملفات مساندة: `hero-salon.jpg`، `og-image.jpg`، `favicon.ico`، `favicon.svg`، `apple-touch-icon.png`.

## تدفق الحجز

1. العميلة تختار الخدمة أو الخدمات.
2. تختار الوقت المطلوب (وموظفة مفضلة لكل خدمة إن أرادت).
3. ترسل طلب الحجز عبر واتساب.
4. موظفة الصالون تتحقق من توفر الوقت والموظفة/الموارد اللازمة.
5. الموظفة تؤكد للعميلة أن الوقت متاح.
6. **بعد تأكيد التوفر فقط** تحوّل العميلة رسوم التأكيد (إن انطبقت).
7. بعد استلام التحويل يُعتمد الحجز.

## الوقت

- الوقت المختار هو **وقت مطلوب** ويخضع لمراجعة الصالون؛ اختياره لا يعني حجزه.
- الصالون يعمل يوميًا من 10 صباحًا إلى 10 مساءً، وآخر موعد يبدأ 9 مساءً.
- **لا حجز لنفس اليوم:** أول يوم متاح للحجز هو الغد (بتوقيت الرياض). من تريد خدمة اليوم تتوجه للصالون مباشرة والدخول فوري؛ تظهر هذه الرسالة تحت حقل التاريخ وعند اختيار تاريخ اليوم، ولا يُرسل الطلب.
- يُحدَّث أول تاريخ متاح عند فتح التقويم أو العودة إلى الصفحة، حتى إذا بقيت مفتوحة بعد منتصف الليل. أي تاريخ محفوظ أصبح اليوم أو قبله لا يُستعاد من المسودة.
- مدة كل خدمة تقريبًا 60 دقيقة. عند اختيار أكثر من خدمة قد تقترح الموظفة وقتًا أبكر.
- الموظفة المفضلة اختيارية؛ الوقت والموظفة يخضعان للتوفر، ويُعتمد الموعد بعد مراجعة الصالون.

## رسوم التأكيد

- 20 ريالًا لكل خدمة تسريحة أو مكياج خاضعة للرسوم (عدد الخدمات الخاضعة × 20).
- **لا يتم التحويل قبل أن تؤكد موظفة الصالون توفر الوقت.** بعد تأكيد التوفر يتم التحويل، وبعد استلام الرسوم يُعتمد الحجز.
- الرسوم لا تُخصم من قيمة الخدمة، وغير مستردة عند إلغاء العميلة بعد تأكيد الموعد.
- باقي الخدمات بلا رسوم تأكيد، وتظل قابلة للطلب ويؤكد الصالون توفرها عبر واتساب.
- بيانات التحويل (مصرف الإنماء — فرع شركة زهرة شيفون للتزيين النسائي — SA9805000068203296839000) تظهر في رسالة واتساب فقط عندما تكون الرسوم أكبر من صفر، وبعد تنبيه صريح بعدم التحويل قبل تأكيد الموظفة.

## حقل `bookable` في الكتالوج

`bookable` اسم تقني قديم داخل الكتالوج، ومعناه الفعلي: **الخدمة تتطلب رسوم تأكيد (requires confirmation fee)**. في الكود تُقرأ عبر `requiresFee(item)`. القيمة `false` لا تعني أن الخدمة غير قابلة للطلب.

## القياس (Analytics)

عند الضغط الناجح على «إرسال الطلب عبر واتساب» يُدفع الحدث `booking_whatsapp_click` إلى `dataLayer`، وإلى `gtag` إن وُجد. الحقول: `items_count`، `services_count`، `products_count`، `fee_services_count`، `items_value`، `confirmation_fee`، `currency`، `has_hair_styling_fee_service`، `has_makeup_fee_service`. لا يُرسل أي بيانات شخصية (اسم، جوال، تاريخ، موظفة، IBAN، نص الطلب). لا يوجد Measurement ID في المشروع حتى الآن.

## التطوير والفحص

يبقى الموقع ثابتًا، دون خادم خلفي أو خطوة بناء أو اعتماد على CDN أثناء التشغيل. Three.js والخطوط والأيقونات محفوظة محليًا مع تراخيصها.

```bash
python3 -m http.server 4173 --directory .
```

للفحص من طرفية أخرى:

```bash
python3 -m pip install -r tests/requirements.txt
python3 -m playwright install chromium
python3 tests/browser_smoke.py
python3 tests/booking_date_smoke.py
python3 tests/hero_smoke.py
```

يمكن تغيير العنوان بمتغير `SMOKE_BASE_URL`. يستخدم الفحص Chromium المثبت في `/usr/bin/chromium` إن توفر، وإلا نسخة Playwright. يمكن تشغيل فحص الحجز على WebKit باستخدام `SMOKE_BROWSER=webkit python3 tests/browser_smoke.py` بعد `python3 -m playwright install webkit`. لا ترسل هذه الفحوص رسائل واتساب؛ تتحقق من الرابط والنص محليًا.

### سفاري والحركة

- المشهد يعتمد على WebGL2، مع سقف لدقة الرسم ومعدل تحديث 30 إطارًا للأجهزة ذات اللمس. يتوقف الرسم عندما يغيب المشهد أو تصبح الصفحة مخفية، ويمكن إيقاف الحركة من الزر الظاهر.
- عند تفضيل تقليل الحركة أو توفير البيانات لا يُحمّل المشهد تلقائيًا. تبقى صورة WebP محلية ثابتة مع زر «تشغيل الحركة» للتشغيل الاختياري دون تغيير إعدادات الجهاز.
- عند فشل WebGL أو تحميل وحدته تتحرك الصورة البديلة بحركة خفيفة؛ يتحكم الزر نفسه في تشغيلها وإيقافها، وتتوقف خارج الشاشة وعند إخفاء الصفحة. يظل الحجز قابلًا للاستخدام.
- فقدان سياق WebGL يعيد الصورة البديلة؛ يستأنف المشهد عند استعادة السياق مع الحفاظ على اختيار المستخدم لإيقاف الحركة. تتقدم حركة المجسم بالوقت الفعلي حتى عند انخفاض معدل الإطارات.
- لوحة الطلب تراعي `visualViewport` عند ظهور لوحة مفاتيح الآيفون، ومساحات الشاشة الآمنة. لا تُعترض حركات اللمس والتمرير من أجل المؤثر.
- فحص WebKit على Linux يثبت سلوك المحرك في بيئة الاختبار، ولا يغني عن معاينة إصدار سفاري المطلوب على جهاز آيفون حقيقي، خصوصًا لوحة المفاتيح وأداء GPU.

إصدارات الأصول ومصادرها في `THIRD_PARTY.md`. `design-qa.md` يسجل المراجعة البصرية ونتائج الفحص قبل النشر.
